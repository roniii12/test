# Agent Guide — Internationalization (i18n)

> **Scope:** `apps/storefront/src/i18n/`
>
> **You are responsible for:** Translation files, locale switching, and ensuring all user-facing text is translatable.

---

## How i18n Works

Custom lightweight i18n using React Context — no frameworks (no `next-intl`, no `react-i18next`).

```
I18nProvider
  ├── Stores current locale (state)
  ├── Provides t() function via context
  └── Resolves dot-path keys against locale JSON

Usage:
  const { t, locale, setLocale } = useTranslation();
  t("product.addToCart")  → "הוסף לסל" (he) / "Add to Cart" (en)
```

## File Structure

```
i18n/
├── I18nProvider.tsx    ← Context provider + resolver + useTranslation hook
├── index.ts           ← Re-exports: { useTranslation } from I18nProvider
└── locales/
    ├── he.json        ← Hebrew translations (default)
    └── en.json        ← English translations
```

## Translation File Format

Nested JSON with dot-path access:

```json
{
  "product": {
    "addToCart": "הוסף לסל",
    "details": "פרטי מוצר",
    "price": "מחיר"
  },
  "cart": {
    "title": "סל הקניות",
    "empty": "הסל ריק"
  },
  "nav": {
    "home": "עמוד הבית"
  }
}
```

Access: `t("product.addToCart")` → `"הוסף לסל"`

## Adding a New Translation Key

1. Add the key to **both** `he.json` and `en.json`
2. Use it in the component: `t("section.keyName")`

```json
// he.json
{
  "testimonials": {
    "title": "מה הלקוחות אומרים"
  }
}

// en.json
{
  "testimonials": {
    "title": "What Our Customers Say"
  }
}
```

## Adding a New Locale

1. Create `locales/<code>.json` (e.g., `ar.json`)
2. Import it in `I18nProvider.tsx`:
   ```typescript
   import arLocale from "./locales/ar.json";
   const locales = { he: heLocale, en: enLocale, ar: arLocale };
   ```
3. The locale can be activated via `setLocale("ar")`

## Rules

- **Default locale is Hebrew (`he`)** — this is the primary language
- **Fallback:** If a key is missing, `t()` returns the key string itself
- **All user-facing text** must use `t()` — never hardcode Hebrew/English strings in components
- **Exception:** Content from PageConfig (product names, category names, etc.) is already in the correct language in the config and doesn't go through `t()`
- **Direction:** Managed by `ThemeProvider`, not i18n. When switching to English, also call `toggleDir()` or `setDir("ltr")`

## Direction Switching

The `ThemeSwitcher` component provides buttons to:

- Switch locale: `setLocale("en")` / `setLocale("he")`
- Switch direction: `setDir("ltr")` / `setDir("rtl")`

These are independent — you can have RTL English or LTR Hebrew (edge case, but possible).

## Important: Content vs UI Text

| Type                                      | How It's Handled                  | Example                      |
| ----------------------------------------- | --------------------------------- | ---------------------------- |
| **UI text** (buttons, labels, titles)     | `t("key")` via i18n               | "Add to Cart", "Back"        |
| **Content** (product names, descriptions) | Direct from PageConfig/SiteConfig | "מחסן מתכת פרמיום"           |
| **SEO** (title, description)              | From `SiteConfig.seo`             | Set in `layout.tsx` metadata |
